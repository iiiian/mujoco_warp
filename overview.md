# MuJoCo Warp codebase overview

MJWarp runs batched MuJoCo-style dynamics with [Warp](https://github.com/NVIDIA/warp) kernels. The public surface is `mujoco_warp/__init__.py`; implementation and nearby `*_test.py` files live in `mujoco_warp/_src/`. A host `mujoco.MjModel` is converted to device-oriented `Model` and `Data` arrays by `io.put_model` and `io.make_data`/`io.put_data`. `Data` has a leading world dimension for many arrays; contact storage and constraint storage have distinct capacity limits. Most top-level Python functions schedule kernels (`@wp.kernel`) rather than doing the numerical work themselves.

## One simulation step

`forward.step(m, d)` calls `forward.forward(m, d)`, then an integrator. The major data flow is:

1. **Position:** `fwd_kinematics` computes body/geom transforms, centers of mass, flex geometry and tendon paths. `fwd_position` builds joint-space inertia `d.M`, detects contacts (`d.contact`), assembles constraints (`d.efc`), and computes actuator transmissions. With sleeping enabled it also wakes bodies and forms islands.
2. **Velocity:** `fwd_velocity` computes actuator/tendon velocities, passive forces, and the recursive-Newton–Euler bias force `d.qfrc_bias`.
3. **Forces:** `fwd_actuation` computes actuator forces; `fwd_acceleration` forms `qfrc_smooth = qfrc_passive - qfrc_bias + qfrc_actuator + qfrc_applied` (plus external body forces) and solves `M qacc_smooth = qfrc_smooth`.
4. **Constraints:** `solver.solve` adjusts acceleration for contact, friction, limits and equalities, yielding `d.qacc` and `d.qfrc_constraint`. Position-, velocity- and acceleration-stage sensors run at their corresponding stages.
5. **Time update:** `euler`, `rungekutta4`, or `implicit` advances velocity, position, activation and time. `step1`/`step2` split the pipeline around setting control inputs; they are not simply two halves of RK4.

Entry points: [`forward.py`](mujoco_warp/_src/forward.py) (`step`, `forward`, `fwd_position`, `fwd_velocity`, `fwd_acceleration`).

## Functionality map

| Functionality | Location and algorithm sketch |
| --- | --- |
| Model/data layout and conversion | [`types.py`](mujoco_warp/_src/types.py) defines `Option`, `Model`, `Data`, `Contact`, `Constraint`; [`io.py`](mujoco_warp/_src/io.py) (`put_model`, `make_data`, `put_data`, `get_data_into`) copies MuJoCo metadata/state into Warp arrays, precomputes layouts and allocates batched workspaces. `set_const.py` prepares model-dependent constants. |
| Kinematics and smooth dynamics | [`smooth.py`](mujoco_warp/_src/smooth.py) (`kinematics`, `com_pos`, `com_vel`, `crb`, `rne`) traverses body trees for transforms and spatial velocities; composite rigid-body recursion accumulates inertia upward and projects it onto DOFs to form `M`; recursive Newton–Euler computes bias forces. `tendon`, `transmission` and `flex` handle their position-dependent geometry and Jacobians. |
| Collision broadphase | [`collision_driver.py`](mujoco_warp/_src/collision_driver.py) (`collision`, `nxn_broadphase`, `sap_broadphase`) filters candidate geom pairs and performs bounding-sphere/AABB checks. NXN tests a model-time prefiltered pair list; SAP projects bounds onto one fixed axis, sorts endpoints and sweeps overlapping intervals. Both feed candidate pairs to narrowphase; sleeping can add an incremental pass for newly awakened bodies. |
| Collision narrowphase | The dispatch table and pipeline are in `collision_driver.py`. [`collision_primitive.py`](mujoco_warp/_src/collision_primitive.py) / `collision_primitive_core.py` use shape-specific geometric formulas; [`collision_convex.py`](mujoco_warp/_src/collision_convex.py) / `collision_gjk.py` use support mappings, GJK distance and EPA/CCD penetration/manifold handling for convex pairs; [`collision_sdf.py`](mujoco_warp/_src/collision_sdf.py) evaluates signed-distance fields and gradients; [`collision_flex.py`](mujoco_warp/_src/collision_flex.py) detects/filter flex contacts, including sweep-and-prune and contact reduction. [`collision_core.py`](mujoco_warp/_src/collision_core.py) mixes contact parameters and writes contact records. These modules find contacts; they do **not** solve contact impulses/forces. |
| Constraint assembly | [`constraint.py`](mujoco_warp/_src/constraint.py) (`make_constraint`) emits equality, friction, joint/tendon-limit and contact rows into `d.efc`: Jacobian `J`, reference acceleration `aref`, impedance-derived diagonal `D`, row metadata and sparse indices. Contact Jacobians project relative point motion onto normal/friction directions; cone choice changes the rows/solver evaluation. This is the constraint *assembly* stage. |
| Smooth linear solve | `smooth.py` (`factor_m`, `solve_m`, `factor_solve_i`) factors the SPD inertia matrix and solves for unconstrained acceleration. Small/dense blocks use Cholesky; oversized tree-structured blocks use sparse LDL. [`block_cholesky.py`](mujoco_warp/_src/block_cholesky.py) supplies tiled blocked kernels. This solve is distinct from the iterative constraint solver. |
| Collision/constraint resolution | [`solver.py`](mujoco_warp/_src/solver.py) (`solve`, `_solve`, `_solver_iteration`) minimizes the constrained acceleration objective. It evaluates active/inactive/contact-cone constraint states and forces from `J*qacc - aref`, performs line search, updates gradient, then uses conjugate gradient with `M` preconditioning or Newton with a Hessian built from `M` and active `Jᵀ D J` (plus elliptic-cone terms). Newton factors the Hessian with Cholesky. Iteration stops on tolerance or iteration count; sleeping can compact active DOFs. |
| Islands and sleep | [`island.py`](mujoco_warp/_src/island.py) unions constraint-connected body trees with disjoint-set operations, labels/maps island DOFs and constraints and compacts active DOFs. [`sleep.py`](mujoco_warp/_src/sleep.py) tracks awake trees and wakes them on motion, tendon/equality/contact interactions. |
| Actuation, passive forces, integration | `forward.py` (`fwd_actuation`, `euler`, `rungekutta4`, `implicit`) computes gain/bias/activation-dependent actuator forces and integrates the state. [`passive.py`](mujoco_warp/_src/passive.py) accumulates passive joint/tendon/flex/fluid-type forces. [`derivative.py`](mujoco_warp/_src/derivative.py) computes velocity derivatives of smooth forces used by implicit integration. |
| Inverse dynamics, sensors, utilities | [`inverse.py`](mujoco_warp/_src/inverse.py) forms forces required for specified acceleration, subtracting passive and constraint forces from inertia/bias terms. [`sensor.py`](mujoco_warp/_src/sensor.py) evaluates sensors by position/velocity/acceleration stage. [`support.py`](mujoco_warp/_src/support.py) provides Jacobians, mass-matrix multiplication, state and contact-force helpers; `math.py` contains spatial algebra. |
| Rendering and rays | [`render.py`](mujoco_warp/_src/render.py), `render_util.py`, [`ray.py`](mujoco_warp/_src/ray.py), and [`bvh.py`](mujoco_warp/_src/bvh.py) implement batch ray-based rendering, primitive/mesh/flex ray tests, and BVH construction/refitting. This BVH is primarily for ray/render traversal; start with `collision_driver.py` for physics broadphase. |

## Study roadmap

1. **Run a small case.** Read `README.md`, `mujoco_warp/__init__.py`, and a small `forward_test.py` case. Follow `put_model → make_data → step`; inspect `Model`, `Data`, `d.qpos`, `d.qvel`, `d.qacc`, `d.contact`, and `d.efc`. Use `uv run pytest mujoco_warp/_src/forward_test.py -k <case>` for a targeted experiment.
2. **Trace one step.** Read `forward.step`, `forward.forward`, `fwd_position`, `fwd_velocity`, `fwd_acceleration` in call order. Draw the dependency chain from state to `M`, contacts, `J`, smooth acceleration, constrained acceleration and next state.
3. **Understand the unconstrained system.** Follow `smooth.kinematics → com_pos → crb → factor_m/solve_m` and `com_vel → rne`; use `smooth_test.py` to check each intermediate. Focus on tree indexing, spatial vectors and sparse-versus-dense mass storage.
4. **Follow one contact.** Trace `collision_driver.collision → broadphase → primitive_narrowphase` for a sphere/plane example, then `constraint.make_constraint` contact kernels. Compare `d.contact` (geometry/material) with `d.efc` (solver rows/Jacobian). Read `collision_driver_test.py` and `constraint_test.py` alongside.
5. **Study resolution.** Trace `solver.solve → init_context → _solver_iteration`, then `_update_constraint`, `_linesearch`, and `_update_gradient`; start with a one-contact pyramidal-cone case and only then inspect elliptic cones, Newton Hessian assembly and active-DOF compaction. Use `solver_test.py`.
6. **Branch into interests.** For deformables follow `smooth.flex → collision_flex → constraint` and `flex_test.py`; for integrators/controls use `forward.py`, `derivative.py`, `passive.py`; for batch performance inspect `io.py` capacities, kernel launch dimensions, `warp_util.py` and `benchmarks/`; for rendering study `render.py → ray.py → bvh.py`.

Tests usually sit beside their implementations. Prefer a focused test during exploration; the project's full-suite command is `uv run pytest -n 8` when preparing a PR.
